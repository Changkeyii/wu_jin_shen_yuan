# 章节视频插入规范

> 适用：独立剧情模式「万灵记忆」与序章。
> 视频只出现在理解会发生转折的地方，不替代关卡、战斗和对话。
> 播放必须使用 `Video.VideoPlayer`，路径相对 `assets/`，例如 `video/story_c01_open.mp4`。

---

## 一、什么时候才上视频

必须同时满足：

1. 这一刻改变玩家对世界、身份或代价的理解；
2. 静态对话、立绘或战斗演出撑不住空间感、仪式感或时间跨度；
3. 看完后玩家能立刻做一个选择、进入一场战斗，或解锁下一章。

不上视频：

- 普通教学、日常委托、重复扫荡；
- 纯数值结算、强化、分解、市场；
- 只为“显得高级”而加的过场；
- 尚未揭示的后期真相。

原则：

> 视频负责让人“看见”，对话负责让人“决定”，战斗负责让人“承担”。

## 二、三种插入位置

| 类型 | ID 后缀 | 插入点 | 能否跳过 | 时长 |
|---|---|---|---|---|
| 开章映像 `open` | `:video:open` | Stage A 调查开始前 | 可跳过，须看完关键字幕或 2 秒后才出现跳过 | 6–10 秒 |
| 战前仪式 `pre` | `:video:pre` | Stage C Boss 对话之后、战斗之前 | 可跳过 | 5–8 秒 |
| 战后余味 `after` | `:video:after` | Stage C 胜利之后、奖励之前 | 首通建议看完；回放可跳过 | 6–12 秒 |
| 卷末抉择 `finale` | `:video:finale` | 第 5/10/20/30/40 章终局选择前 | 不可用倒计时跳过选择；映像本身可跳过 | 8–15 秒 |

终局三选一界面本身不是视频。视频只把代价放到眼前，选择仍由独立确认界面完成。

## 二·五、三种内容层

一段剧情演出可以组合以下三种层：

| 层 | 资源 | 作用 | 时长/条数 |
|---|---|---|---|
| **视频** | `Video.VideoPlayer` 播片 | 空间、动作、仪式感 | 5–15 秒 |
| **台词** | 文字 + 头像（塔灵/守塔人/主角），逐句确认 | 人物立场、选择、情感 | 1–4 句/节点 |
| **插图旁白** | 静态图 + 字幕条/旁白框，可手动翻页 | 世界氛围、回忆、过渡 | 1–3 张/节点 |

### 使用原则

1. **同一节点不同时塞满三种**。视频用于大场面；台词用于人物交锋；插图用于交代背景和留白。
2. **台词必须写给具体角色**：标 `角色名 + 语气 + 台词`，由头像/立绘承载，不烧进视频画面。
3. **插图配旁白**：插图用统一剧画风格（见 `18-第一批章节视频分镜.md` 插图段），旁白 1–2 句，短、意象化。
4. 视频+台词连续时：视频放音，随后切台词确认，再进战斗/选择；播放不抢台词节奏。
5. 插图在 `CampaignCatalog` 里定义为 `kind = "illustration"` 节点，可单独插入剧情，不依赖视频。

## 二·六、台词与旁白的书写格式

所有台词写入分镜文档，格式固定：

```lua
dialogue = {
    { speaker = "塔灵", tone = "平静", text = "塔记得你。它不记得你何时决定不再回头。" },
    { speaker = "你", tone = "自问", text = "封门那天，我到底在替谁做决定。" },
},
```

旁白（插图用）：

```lua
narrations = {
    { image = "assets/image/story_c06_illus_empty_1.png", text = "有人曾经在这里刻下名字，又在同一天亲手划去。" },
},
```

规则：

- `speaker` 必须来自 `03-角色与名词表.md`，新角色先登记；
- 每句 ≤ 22 字（移动端阅读）；
- 台词不解释制度，只表达立场；
- 旁白 1–2 句，禁止三段以上的说明。

## 四、镜头与风格

统一视觉：

- 竖屏 9:16，720p，无字幕烧录（字幕由游戏 UI 叠加）；
- **必须对齐现有游戏**：BrawlForge 美式卡通、厚描边、青紫霓虹塔廊、红黑机甲；
- **主角必须出场**：红发青年、黑红机甲、赤焰长枪刃（不是手枪、不是巨剑）；
- 塔灵如出场：青色全息斗篷、面具、数据环，对齐 `tower_spirit_portrait`；
- 生成时必须把主角立绘/序章尾帧作为参考图，禁止纯文本空想；
- 禁止写实石堡、欧洲神殿、空镜无人、血腥肢解。

每段视频必须包含一个核心意象，并只推进一层含义：

| 视频 | 核心意象 | 推进的含义 |
|---|---|---|
| c01_open | 残刃 / 封存门 | 力量来自被封存的记录 |
| c05_after | 空王座 | 提问权还在，否决权尚未交出 |
| c06_open | 空痕 | 有人主动放弃被系统识别 |
| c10_finale | 门 | 门不是怪物，是仍在等人的通道 |
| c17_open | 列车 / 明天 | “一起抵达”会抹掉分别抵达 |
| c20_finale | 双向的手 | 封门同时保护与抛弃 |
| c28_after | 第零席 | 见证者不能坐上决定席 |
| c40_finale | 两侧晨光 | 任何选择都会留下人 |

旁白风格：短句、第二人称或塔灵口吻，不解释制度，不喊救世主。

## 五、运行时插入

建议在 `CampaignCatalog` 节点上标记：

```lua
{
    id = "main:c01:a:intro",
    kind = "video",
    videoId = "story_c01_open",
    src = "video/story_c01_open.mp4",
    skippable = true,
    skipAfterSeconds = 2,
    captions = {
        "有些记录不在塔的高处。",
        "它们只是被封存在无人再问起的地方。",
    },
}
```

播放规则：

1. 使用 `urhox-libs/Video` 的 `Video.VideoPlayer`；
2. 全屏黑底，`objectFit = "contain"`；
3. 字幕叠在视频下方，不烧进画面；
4. 可跳过视频不得跳过随后的选择界面；
5. 失败、重连、回放都从该节点恢复，不自动发奖；
6. 视频结束才允许进入战斗或领奖；
7. 本地不支持播放时，降级为静态插画 + 同样字幕，不阻断主线。

## 六、制作批次与确认

### 第一批（本次）

先生成 8 段新视频（序章 CG 复用现有文件）。默认模型 2.0：

- 8 秒 × 5 段 ≈ 8000 积分当量
- 10 秒 × 2 段 ≈ 4000
- 12 秒 × 1 段 ≈ 2400

粗估合计约 **14400 积分当量**，仅供确认参考，实际按上游 token 扣费。

### 生成约束

- `mode = first_frame` 或 `text_to_video`；
- 竖屏 `ratio = 9:16`；
- `generate_audio = true`；
- 输出到 `assets/video/`；
- 文件名必须等于视频 ID。

若用户未确认积分，只落文档和镜头脚本，不调用视频生成。

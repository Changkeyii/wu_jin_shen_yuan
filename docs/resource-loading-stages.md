# 分阶段边下边玩（2026-10-09）

本次恢复引擎原有 DWP 图片加载路径，撤销 ImageMemoryBudget 对全局 ImageCache.Get 的替换以及 Texture2D 预算修改。启动时先创建原来的菊花、进度条和背景，再派发下载；不再等待全部游戏素材。

## 分段依据与触发点

| 阶段 | 触发 | 资源与放行条件 |
| --- | --- | --- |
| 启动表现 | 建立 UI 根节点 | 保留原 12 点菊花、尺寸、转速、背景和进度条；下载队列从 Update 才开始执行 |
| 首页 | 登录 | 首页、导航、通用提示/奖励资源以及首页音乐；资源完成且取得存档后放行 |
| 当前引导 | 首份存档确认未完成序章 | 加入塔灵对话资源；仅 step=1 加入序章 CG，恢复到后续教学步骤不重播 CG |
| 下一步准备 | 首页可用，或新手 CG/对话开始 | 老玩家后台准备登塔；新玩家后台准备当前教学目标。只下载文件，不批量创建纹理 |
| 首杀与装备教学 | 确认进入首杀，随后穿戴/分解/强化 | 战斗包含 16 跑步帧和三套完整的 48 帧攻击动作。目标页就绪后才启动教学战斗；首杀期间后台准备装备、背包 |
| 其他功能 | 玩家进入页面 | 市场、图鉴、许愿、活动等分别按页面加载；不登录即预载许愿全部图标 |
| 章节媒体 | 选择具体剧情小节 | 只预下载该节插图/视频。播放视频、进入战斗前确认资源就绪；关闭详情取消尚未派发的媒体预取 |

资源清单由 `scripts/client/ResourceStages.lua` 定义。公共包去重复用，不按页面重复下载。

按当前本地文件计算：首页包 55 个唯一文件，约 10.11 MiB；新手 step=1 在此基础上增加 3 个文件约 18.33 MiB（包含 CG）；登塔包相对首页新增 187 个文件约 14.70 MiB。以上是文件字节量，不是运行内存、网络实际流量或预计等待时间。实际下载会命中引擎本地缓存。

## 调度与异常处理

- 自有预取队列最多两个并发，每帧最多派发两个文件；当前操作优先于后台准备。引擎自动触发的 DWP 请求仍由引擎调度，此限制不代表引擎全部网络请求的总上限。
- 前景进度只统计当前资源包；后台任务不会延长首页菊花，也不会自行弹出加载遮罩。
- 下载失败或超时不标记为就绪。显示重试文字，保留当前画面；重试只补失败项。图片超时 30 秒、视频 180 秒，以前台更新时长计。
- 取消、恢复首页和新一轮请求会使旧导航回调失效。重复 SDK 回调不能重复切页或启动教学。
- 引导输入白名单允许加载重试及已有恢复设置入口。
- 不更改素材尺寸、画质、奖励计算或战斗速度。音效首次使用时加载，战斗音乐不在首页启动时解码。

## 释放规则

- 保留最多两个页面控件树，淘汰时销毁原生控件。
- 只在页面明确淘汰后释放其专属图片缓存，保留当前页面、可见弹窗和剧情战斗仍在使用的图片；不进行全局定时图片淘汰，不接管引擎缓存函数。
- 视频结束或跳过时销毁视频播放器；序章和章节视频容器也显式销毁。

## 验证范围

`tests/startup_memory.lua` 覆盖冷热启动、存档与资源门槛、原菊花结构、背景加载不挡首页、完整攻击帧、失败/超时/重试、重复/失效回调、请求优先级及页面释放保护。导航回归覆盖资源未就绪时不进入、不启动教程，以及返回首页后的旧回调。现有剧情与布局回归继续保留。

这些验证使用可控的 SDK 和控件替身，不等于手机渲染与内存峰值测量。此次黑屏没有取得对应实机日志，因此未将缓存预算调用认定为已证实的唯一根因；本次撤销了该新增启动依赖，并按原启动路径恢复。

## 恢复上一版加载流程（2026-10-09）

实机反馈：后续 `ccc7a5f` 启动优化导致黑屏更长，原生加载表现缺失，菊花后仍有空白和黑屏。该方案新增了 boot 预下载、自有启动树、协程逐帧导入，以及一次 UI.Shutdown / UI.Init 交接。代码回归未覆盖引擎原生加载和手机渲染交接，不能据此认定该方案改善了启动体验。

按用户要求，以 `e0fc5d5`（代码 `ffa0f70`）为基线恢复 main 入口、完整 GameView Start/Stop 时序、LoadingController 和 resources.json；删除后续 Bootstrap、BootScreen、StartupModules、LoadingVisual、StartupTiming 及对应测试。取消 boot 预下载组，恢复 `preload_groups: []`，继续原来的引擎 DWP 路径。之前完成的首页/引导/战斗/其他页面分段下载保持不变。

轻度优化仅保留市场、图鉴、装备页、任务页和 GM 面板在使用时 require，减少首页启动不需要的页面代码初始化。不增加启动画面、等待帧、UI 重建或新的资源门槛。原菊花样式和进度逻辑使用基线实现。

交付检查包含上述基线文件及启动/停止代码的字节比对、现有回归、Lua 语法和修改文件诊断。原生加载是否正常出现及黑屏时长仍以手机验证为准。

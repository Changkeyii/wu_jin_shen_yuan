# 邮件 shared-queue-v3 实现与发布验收

共享记录是邮件的待派发来源，个人邮箱仍由服务端读取个人存档；阅读、领取、收藏、删除、附件规则和100封普通邮件＋200封缓存保持原逻辑。

## 实现入口

- `CloudMailStore` 管理固定云键、实际 JSON 字节检查、公共分桶、版本保护、旧全服记录迁移、缓存、请求超时和预算。
- `SharedMailDelivery` 将源邮件转入个人邮箱，同时保存送达账本、个人审计并删除个人源记录。以上与角色存档处于同一个 `BatchCommit`。
- `ServerMain` 显式注入新服务；GM 个人发件使用 List 队列，不再用 Message 作为新邮件来源。旧路径仅用于历史兼容。
- 全部个人存档提交经 `PlayerProfileRepository:Commit`，用独立 `storageVersion` 和不可刷新 Quota 计数器保护。战斗的内存更新不增加云写入。

## 云键和保护阈值

公共归属 UID 与排行榜一致，为 `162878756`，所有实例必须进入同一正式游戏的云数据空间。

| 范围 | 键 | 保护阈值 |
|---|---|---|
| 公共 | `mail_v3_public_01`～`mail_v3_public_16` | 每 List 32条，共512条 |
| 公共 | `mail_v3_directory`、`mail_v3_directory_rev` | 目录 JSON ≤4096字节 |
| 玩家 | `mail_v3_pending` | 与未完成交接审计合计≤300条 |
| 玩家 | `mail_v3_ledger`、`mail_v3_player_rev` | 512个有效序号，JSON ≤4096字节 |
| 玩家 | `mail_v3_audit` | 最近64条已完成记录；未确认旧任务不淘汰 |
| 玩家 | `abyss_profile_write_v3` | 角色存档专用 Quota 版本；不刷新、不重置 |

公共固定新增18个键，每 UID 固定新增5个键。单封源记录 JSON ≤8192字节。满容量和超出字节阈值均拒绝新增，不截断正文、不删除未交接奖励。最大序号为2147483647；512个最大36进制序号、64字节写事务ID及元数据的测试 JSON 为3729字节。

## 原子性、超时和同步

个人派发包含：角色 Quota＋个人存档及其投影、账本 Quota＋账本、投递审计、源记录 ListDelete。全服派发包含个人存档和账本送达标记；领取、删除个人邮件不会移除有效公共邮件的标记。公共发布、迁移及过期清理保护目录并原子更新桶计数、桶版本和源记录。

读请求10秒超时后释放请求和同步标记。失败同步按5、15、30、60秒重试，最多60秒；常规在线同步每30秒。目录缓存60秒，合并同时发生的读取，仅读取改变版本的桶。过期清理每批最多8条；已过期公共邮件即使仍在缓存或等待清理，也停止派发，并在玩家下次同步时清理对应送达标记。

写超时进入待确认状态，不把“重新读到旧值”当成失败：原写可能仍在途。存档会话暂停新写入及战斗内存修改，通过云存档写事务ID/版本和迟到结果确认。确认后加载权威存档重新发快照。公共/个人队列写超时冻结对应写作用域并重新读取目录/账本；不自动重新创建来源。

旧实例保存被版本保护拒绝，需重新同步该会话。断线、重连回调验证会话代次。异常源记录保留并记录日志，不影响其他合法来源；结构无效的目录或账本则暂停该范围同步。

邮件请求限制为每实例读、写各60次/分钟。后台各最多40次，预留20次给前台。后台读取再分为共享同步28次和旧 GM 消息12次，防止旧队列饿死共享同步；两条轮询均轮换玩家顺序。收到 `-429` 延后60秒。实际用户人数超过预算时同步会延后，客户端显示待同步状态。

`ServerCloudGateway:RequestTotals()` 统计所有经网关调用的玩法、邮箱、GM、排行榜请求。GM投递查询显示本分钟合计，并返回峰值、协议和平台限流范围尚未验证的标记。该统计按网关调用计数，不能推断平台是否按批次、操作数、UID或游戏限流。

## GM 和客户端

GM发件返回稳定来源 `mailId`；它与个人邮箱内的展示邮件ID用途不同。玩家点击邮箱会主动同步，`Mail.List` 保留 `items` 和 `deliveryPending`，增加 `syncState`、`syncError`、`retryAt`、`deliveryProtocol`。云读取失败显示同步未完成，写待确认显示确认提示。

`Admin.MailDeliveryStatus` 可带来源 `mailId`，GM玩家查询页增加选填框。个人/全服来源为 pending，落个人存档为 delivered，旧任务未确认为 handoff_pending，结果待确认为 confirming；读失败为 sync_failed。查不到记录且无审计证据为 unknown，不能当作未派发。

## 历史兼容

旧 `abyss_broadcast_mail_v1` 每批最多迁移8条，源记录删除和新桶记录保存处于同一事务。新记录保留 `legacyBatchId` 和原有效期；原公共来源的0/缺省有效期继续作为永久来源。既有 `receivedBroadcasts` 或旧业务订单邮件转换为新账本标记，不重复创建邮件。

旧个人 GM_COMMAND/PERSONAL_MAIL 保留原 `commandId`，先保存邮件及未完成交接凭据，随后删除旧 Message，再用保护事务将凭据标为完成。删除回调丢失时，成功读取已读/未读两类队列并确认旧源已不存在，才能完成交接。失败凭据保留并在下次同步重试；其间即使个人邮件已领取/删除也不补发。

历史已读任务只迁移有成功或已知不支持动作失败凭据的记录。没有证据的历史任务不自动重放。旧实例已经丢失的内存邮件无法恢复。

## 本地验证

`tests/shared_mail_v3.lua` 使用真实网关、仓库、存档服务和共享服务，底层替换为支持完整事务回滚的引擎形状云接口。覆盖跨实例/新玩家、并发只成功一个、领取删除重启、旧断线覆盖、源删除或存档失败、回调丢失/迟到、在途写确认、快速重连、读超时、邮箱满、坏记录、缓存内到期和请求统计。

`tests/shared_mail_limits.lua` 覆盖16×32桶、300条合计及并发准入、64条审计及保留未完成凭据、8192/8193实际 JSON 字节边界、512序号编码、失效标记清理、目录缓存/读取合并、前台预算和限流。

`tests/shared_mail_legacy.lua` 覆盖历史全服别名和期限、旧个人交接失败后重启与邮件删除、成功凭据转换以及无证据不重放。既有附件/红点/客户端刷新/免广告身份等回归继续执行。旧活动视图测试桩补齐原有 `RewardVideo.ActionText` 接口，仅修改测试桩。

## 正式发布前必须完成

1. 在与正式玩家数据隔离的开发云验证真实 SDK 返回形状、ListAdd返回ID、Score JSON是否需要解码、Message删除成功/不存在的结构。
2. 实测4096字节目录/账本、8192字节来源、固定18＋5个键、512全服/300待处理条目、满邮箱个人存档大小。任何平台硬限制更低均停止发布，不截断内容。
3. 同时提交两个使用相同期望 Quota 版本的事务，验证恰好一个成功，以及存档写入/源删除失败的全事务回滚。
4. 验证平台300读/写每分钟及48 MB/分钟的具体限流范围和批次计数方式，结合GM合计请求和所有玩法满负载检查。
5. 暂停GM发件；在新版迁移现有持久来源，保留异常记录；退出所有旧生产写入实例，确保它们不再用无保护代码写角色存档。
6. 用测试账号在两实例、离线登录及有效期内新账号验收；确认迁移完成后再启用正式GM派发。

本次仿真验证和 Maker 开发构建均不代表以上真实云与正式服验收已通过。本次不操作正式玩家UID、不发送测试奖励、不退出正式实例，也不执行正式发布。

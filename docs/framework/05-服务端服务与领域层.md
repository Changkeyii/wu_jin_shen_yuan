# 05 · 服务端服务与领域层（services + domain）

> 这一层实现所有玩法逻辑，是框架中"玩法相关"最重的部分，但**架构模式高度可复用**：
> - **领域层是纯函数**：`GameEngine.XXX(state, ...) → proposal`，不含任何 IO，可单测。
> - **服务层负责编排**：会话生命周期、异步 IO（云存储）、每玩家串行、增量下发。
> - **proposal 协议**：领域函数返回统一结构，服务层据此决定提交/下发。

## 1. proposal 协议（领域层统一返回结构）

所有领域函数 `f(inputState, ...) → proposal` 遵循统一结构：

```lua
proposal = {
    ok = true|false,                 -- 是否成功
    state = <新状态>,                 -- ok 时：变更后的完整状态
    delta = { events={...}, changes={...}, kind=... },  -- 要下发给客户端的增量
    commit = { kind = "none"|"persist"|..., ... },      -- 是否需要持久化
    error = { code=..., reason=... },  -- 失败时的错误
    market = {...},                  -- 市场域返回值（可选）
    cloudOperations = {...},         -- 跨域云操作（并入事务，可选）
}
```

**commit.kind 语义**：
- `"none"`：运行时状态变化（如战斗 tick 的纯表现），不写云、可不下发快照。
- `"persist"` 或其他：需要 `repository:Commit` 落库。

`GameEngine` 里三个辅助构造：

```lua
local function buildCommit(previousRevision, state)   -- 构造 commit（含 revision+1）
local function buildDelta(previous, current, kind, events, inventoryChanged, equippedChanged)  -- 构造 delta
local function finalize(inputState, workingState, now, kind, events, inventoryChanged, equippedChanged, combatOnly)
    -- 统一收尾：refreshDerived → buildCommit → buildDelta → 组装 proposal
local function noCommit(inputState, now, kind, events)      -- commit.kind="none"
local function failure(inputState, now, code, reason, events) -- 失败 proposal
```

### 2.2 Apply 流程（核心）

```lua
function PlayerProfileService:Apply(userId, operationName, mutator, onComplete)
    return self:_apply(userId, operationName, nil, mutator, onComplete)
end

function PlayerProfileService:_apply(userId, operationName, commandId, mutator, onComplete)
    local session = self.sessions[userId]
    if not session or not session.state then
        onComplete(Result(false, {}, "PROFILE_NOT_LOADED", "player profile is not loaded")); return
    end
    local before = session.state
    local persistedBefore = session.persistedState or before

    -- GM 幂等：同 commandId 不重复执行
    if commandId and HasAppliedGmCommand(before, commandId) then
        onComplete(Result(true, { state=before, committed=false, alreadyApplied=true, status="alreadyApplied" })); return
    end

    -- 1) 调领域纯函数
    local ok, proposal = pcall(mutator, before, self.clock())
    if not ok then onComplete(Result(false, {}, "DOMAIN_ERROR", proposal)); return end
    if type(proposal) ~= "table" then onComplete(Result(false, {}, "INVALID_PROPOSAL", "domain operation did not return a proposal")); return end
    if not proposal.ok then onComplete(Result(false, { delta=proposal.delta }, proposal.error.code, proposal.error.reason)); return end

    -- 2) GM 命令必须真正产生持久化变更
    if commandId then
        if not proposal.commit or proposal.commit.kind == "none" then
            onComplete(Result(false, {}, "IDEMPOTENCY_REQUIRES_COMMIT", "idempotent operation must produce a persistent mutation")); return
        end
        AppendAppliedGmCommand(proposal.state, commandId)
    end

    -- 3) 校验新状态
    local valid, validationError = GameStateSchema.ValidateState(proposal.state)
    if not valid then onComplete(Result(false, {}, validationError.code, validationError.reason)); return end

    -- 4) 无持久化变更（纯运行时）
    if not proposal.commit or proposal.commit.kind == "none" then
        onComplete(Result(true, { state=before, delta=proposal.delta, committed=false })); return
    end

    -- 5) 持久化：revision+1，跨域操作并入同批事务
    self.repository:Commit(userId, persistedBefore, proposal.state, "abyss " .. tostring(operationName), function(commitResult)
        if not commitResult.ok then onComplete(Result(false, { rollbackRevision=before.revision }, commitResult.code, commitResult.reason)); return end
        local current = self.sessions[userId]
        if current ~= session then onComplete(Result(false, {}, "STALE_SESSION", "session changed while cloud transaction was pending")); return end
        session.state = proposal.state
        session.persistedState = TableUtils.DeepCopy(proposal.state)
        onComplete(Result(true, { state=session.state, delta=proposal.delta, committed=true, alreadyApplied=false, market=proposal.market }))
    end, proposal.cloudOperations)
end
```

### 2.4 离线收益三阶段

```
登录 Attach ──► FreezeOfflineReward   冻结账本（GameEngine.FreezeOfflineReward）
                 │  session.offlineLedger = { seconds, reward, items }
                 ▼
PreviewOffline ─► 签发幂等 quoteToken，返回 reward 预览
                 ▼
ClaimOffline  ──► Apply("collect offline reward", mutator=GameEngine.ClaimOfflineReward)
                 │  成功后：session.offlineReceipts[token] = result（10 分钟幂等重放）
                 ▼
                 session.offlineLedger = nil（清空）
```

**幂等领取**：同一 `quoteToken` 第二次领取直接返回缓存的 `offlineReceipts[token]`，不会重复结算。

## 3. IdleRuntimeService（挂机自动战斗驱动器）

职责：每帧检测在线玩家的 `autoRun` 状态，按战斗节奏把"自动战斗 tick"排队执行。**与玩家主动命令共用同一个 OperationQueue**，保证同玩家串行。

```lua
function IdleRuntimeService:Update(timeStep)
    for _, userId in ipairs(self.profileService:OnlineUserIds()) do
        local state = self.profileService:GetState(userId)
        -- 交互事件超时：服务端权威强制 skip
        if state and state.pendingEvent and not self.pending[userId] then
            self:_enqueueEventTimeout(userId, state.pendingEvent)
        end
        if state and state.autoRun and state.currentMonster
            and not state.pendingStoryGate and not state.pendingEvent then
            -- 按怪物攻击间隔/狂暴时间动态计算 tick 间隔
            local interval = computeInterval(state)
            if elapsed >= interval and not self.pending[userId] then
                self:_enqueueTick(userId, interval)
            end
        end
    end
end
```

`_enqueueTick` 用 `ApplyRuntime` 调 `GameEngine.AdvanceCombatTick(state, rng, now, elapsedSeconds)`，事件通过 `onDelta` 下发；同玩家同时只允许一个 tick 在队列（`pending[userId]` 令牌）。

> 挂机 tick 用 `ApplyRuntime`（不落库），真正有掉落/扣资源时才在领域层返回 `commit.kind="persist"` 的 delta 触发落库。这是"高频表现 + 低频持久化"的典型做法。

### 4.2 领域函数模式（以 Strengthen 为例）

```lua
function GameEngine.Strengthen(inputState, slotId, now)
    now = nowInteger(now)
    local working = stateCopy(inputState, now)          -- 深拷贝，绝不改入参
    local events = {}

    local equipped = working.equipped or {}
    local itemId = equipped[slotId]
    local item = itemId and findItem(working, itemId)
    if not item then
        return failure(inputState, now, "EQUIPMENT_NOT_FOUND", "装备不存在")
    end
    -- ... 成本计算、VIP 折扣、强化上限、roll 新属性 ...
    events[#events+1] = event("equipment_strengthened", { slot=slotId, enhance=item.enhance, ... })

    return finalize(inputState, working, now, "strengthen",
        events, false, false, false)
end
```

**不可变约定**：
1. 入参 `inputState` 绝不被修改，一律 `stateCopy` 深拷贝。
2. 事件用 `event(kind, fields)` 统一构造。
3. 成功路径统一走 `finalize`（它负责 `refreshDerived`、`buildCommit`、`buildDelta`、组装 proposal）。
4. 失败路径统一走 `failure`（返回错误码 + 错误原因）。

## 8. 服务层组合（以"强化"命令为例完整链路）

```
GameCommands handler（Game.Strengthen）
   │  AsyncMutation(services, "strengthen equipment", mutator)
   │     └─► services.profileService:Apply(uid, "strengthen", mutator(state,payload,now)=GameEngine.Strengthen)
   │             ├─► GameEngine.Strengthen(state, slot, now) → proposal
   │             ├─► ValidateState(proposal.state)
   │             ├─► repository:Commit(old, new, "abyss strengthen", onComplete, proposal.cloudOperations)
   │             │      └─► gateway:BatchCommit(...)   ← 原子写云
   │             └─► onComplete(result)
   │  services.sendDelta(uid, result.data.delta)   ← 下发增量给客户端
   │  done(response.ok, response)                   ← 回命令响应
   └─► CommandRouter._finish → SendRemoteEvent(RESPONSE)
```

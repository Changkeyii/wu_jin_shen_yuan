# 04 · 服务端数据层（ServerCloudGateway + PlayerProfileRepository）

> 数据层解决"玩家档案如何在 serverCloud 云变量中落地"。核心设计：
> - **Gateway 层**：把 serverCloud 的 Score / Money / List / Item / Message / Quota / Rank 全部封装成统一回调式 API（`{ok, code, reason, data}`）。
> - **Repository 层**：把"一份完整状态"映射成"多组云变量操作"，并保证 **原子事务提交**。
> - **事务模型**：玩家档案 + 市场账本 + 对方信箱可以**同批原子提交**，要么全部生效、要么全部回滚。

文件：
- `scripts/server/dao/ServerCloudGateway.lua`（610 行）
- `scripts/server/repositories/PlayerProfileRepository.lua`（564 行）

## 1. serverCloud 能力全景

| 能力 | 说明 | Gateway 封装 |
|------|------|--------------|
| `Score` | 按 uid 存的 KV 标量/整数 | `ScoreGet/Set/SetInt/Add/Delete` |
| `Money` | 独立记账（整数） | `MoneyGet/Add/Cost` |
| `List` | 每玩家有序列表（挂单/背包用） | `ListGet/GetById/Add/Modify/ModifyKey/Delete` |
| `Item` | 道具计数（name/count/value） | `ItemGet/Add/Use` |
| `Message` | 玩家间消息（信箱） | `MessageSend/Get/MarkRead/Delete` |
| `Quota` | 限额/重置 | `QuotaGet/Add/Reset` |
| `Rank` | 排行榜 | `RankGetList/GetUser/GetTotal` |
| `BatchGet` | 批量读 | `BatchGet` |
| `BatchSet` | 批量写（非事务） | `BatchSet` |
| `BatchCommit` | **原子事务**（唯一事务语义） | `BatchCommit` |

## 2. Gateway 统一回调约定

所有方法都是 **回调式**，返回 `{ ok=true, data=..., code=0, reason="" }` 或 `{ ok=false, data=..., code=..., reason=... }`。

```lua
local function success(data)  return { ok=true,  data=data or {}, code=0, reason="" } end
local function failure(code, reason, data)
    return { ok=false, data=data or {}, code=code or -1, reason=tostring(reason or "serverCloud request failed") }
end
```

统一的事件适配器（把 serverCloud 的 `ok/error` 回调转成统一 result）：

```lua
local function eventsFor(onComplete, mapSuccess)
    requireCompletion(onComplete)
    return {
        ok = function(...)
            local data = {}
            if mapSuccess then data = mapSuccess(...) or {} end
            onComplete(success(data))
        end,
        error = function(code, reason)
            onComplete(failure(code, reason))
        end,
    }
end
```

所有方法都先做**参数白名单校验**，非法参数直接返回 `INVALID_ARGUMENT`，杜绝脏数据进云：

```lua
function ServerCloudGateway:ScoreAdd(userId, key, delta, onComplete)
    if not self:_requireCloud(onComplete) then return end
    if not validateUserId(userId) or not isNonEmptyString(key) or not isInteger(delta) then
        return self:_invalid(onComplete, "ScoreAdd requires integer userId/delta and a non-empty key")
    end
    self.cloud:Add(userId, key, delta, eventsFor(onComplete))
end
```

## 3. 事务提交 `BatchCommit`

**这是整个数据层最重要的 API**：把若干操作打进同一个 `cloud:BatchCommit(description)`，`commit:Commit()` 一次性提交，具备原子性。

```lua
function ServerCloudGateway:BatchCommit(description, operations, onComplete)
    if not self:_requireCloud(onComplete) then return end
    if not isNonEmptyString(description) or not validateOperations(operations) then
        return self:_invalid(onComplete, "BatchCommit requires a description and operations")
    end
    for _, operation in ipairs(operations) do
        if type(operation) ~= "table" or not commitHandlers[operation.kind] then
            return self:_unsupported(onComplete, "BatchCommit contains an unsupported operation")
        end
    end

    local commit = self.cloud:BatchCommit(description)
    local listIds = {}
    for _, operation in ipairs(operations) do
        commitHandlers[operation.kind](commit, operation, listIds)
    end
    -- BatchCommit 是唯一具备事务语义的 gateway 操作
    commit:Commit(eventsFor(onComplete, function()
        return { listIds = listIds }
    end))
end
```

操作类型（`CommitOperation` 常量）：

```lua
ServerCloudGateway.CommitOperation = {
    SCORE_SET = "score_set",  SCORE_SET_INT = "score_set_int",
    SCORE_ADD_INT = "score_add_int", SCORE_DELETE = "score_delete",
    SCORE_DELETE_INT = "score_delete_int",
    MONEY_ADD = "money_add",  MONEY_COST = "money_cost",
    LIST_ADD = "list_add",    LIST_MODIFY = "list_modify",
    LIST_MODIFY_KEY = "list_modify_key", LIST_DELETE = "list_delete",
```

## 4. Repository 的持久化映射策略

### 4.1 存储布局

一份玩家档案在云中拆成三组存储：

| 云存储类型 | Key | 存什么 |
|-----------|-----|--------|
| Score | `abyss_profile` | 档案核心（除背包/大数外的持久化字段，JSON 表） |
| Score | `abyss_schema_version` / `abyss_revision` / `abyss_updated_at` / `abyss_floor` / `abyss_max_floor` / `abyss_level` / `abyss_power` / `abyss_power_value` | 标量索引（排行榜/查询用） |
| Score | `abyss_gold_high/mid/low`、`abyss_fragments_high/mid/low` | 大数金币/碎片（三段式，避开 27 位限制） |

### 4.2 加载 `Load`（三路并行读）

用 `_joinReads` 并发拉取 Score + List + Item 三组数据，全部成功才组装：

```lua
function PlayerProfileRepository:_joinReads(userId, onComplete)
    local remaining = 3
    local finished = false
    local values = {}
    local function receive(name)
        return function(result)
            if finished then return end
            if not result.ok then finished = true; onComplete(Result(false, { source=name }, result.code, result.reason)); return end
            values[name] = result.data
            remaining = remaining - 1
            if remaining == 0 then finished = true; onComplete(Result(true, values)) end
        end
    end
    self.gateway:BatchGet(userId, LOAD_KEYS, receive("score"))
    self.gateway:ListGet(userId, self.Keys.INVENTORY, receive("inventory"))
    self.gateway:ItemGet(userId, self.Keys.CONSUMABLE, receive("items"))
end
```

加载后：
1. 若无 `abyss_profile` 但存在任何子数据 → 报 `ORPHANED_PROFILE`（孤儿数据）。
2. 无任何数据 → `{ missing = true }`，由 Service 走 `StateFactory.Create` 初始化。
3. 有数据 → 组装 `raw`，做 `StateNormalizer.ValidateRawV5BigNumbers` + `StateNormalizer.Normalize`，再校验"归一化后背包行数不变"（防止静默丢数据）。

### 4.3 提交 `Commit`（差异计算 + 原子写）

```lua
function PlayerProfileRepository:Commit(userId, oldState, newState, description, onComplete, extraOperations)
    if oldState and newState.revision <= oldState.revision then
        onComplete(Result(false, {}, "REVISION_MISMATCH", "new state revision must advance"))
        return
    end
    local operations, buildReason = self:_buildOperations(userId, oldState, newState)
    if not operations then
        onComplete(Result(false, {}, "PERSISTENCE_MAP_MISSING", buildReason))
        return
    end
    -- 领域层附带的跨域操作（市场账本、对方信箱）并入同一个 BatchCommit，
    -- 使"扣款 + 摘牌 + 对方入信箱"要么全部生效、要么全部回滚。
    for _, extraOperation in ipairs(extraOperations or {}) do
        operations[#operations + 1] = extraOperation
    end
    if #operations > 1000 then
        onComplete(Result(false, {}, "BATCH_TOO_LARGE", "transaction exceeds serverCloud operation limit"))
        return
    end
    self.gateway:BatchCommit(description or "abyss profile mutation", operations, function(result)
        if not result.ok then onComplete(result); return end
        -- 更新 listId 缓存（LIST_ADD 返回的新 listId）
        ...
        onComplete(Result(true, { state = newState, operationCount = #operations }))
    end)
end
```

### 4.4 差异计算 `_buildOperations`

对背包做"新旧两表 diff"，生成 `LIST_ADD / LIST_MODIFY / LIST_DELETE`：

```lua
local oldItems = IndexInventory(oldState and PersistedInventory(oldState) or {})
local newItems = IndexInventory(PersistedInventory(newState))
local listMap = self.listIds[userId] or {}

for itemId, item in pairs(newItems) do
    local previous = oldItems[itemId]
    if not previous then
        operations[#operations+1] = { kind=operation.LIST_ADD, userId=userId, key=self.Keys.INVENTORY, value=item, resultKey=itemId }
    elseif not TableUtils.DeepEqual(previous, item) then
        local listId = listMap[itemId]
        if not listId then return nil, "missing cloud list id for modified item " .. itemId end
        operations[#operations+1] = { kind=operation.LIST_MODIFY, listId=listId, value=item }
    end
end
for itemId in pairs(oldItems) do
    if not newItems[itemId] then
        local listId = listMap[itemId]
        if not listId then return nil, "missing cloud list id for deleted item " .. itemId end
        operations[#operations+1] = { kind=operation.LIST_DELETE, listId=listId }
    end
end
```

## 5. 跨域事务示例：市场购买

玩家购买一件挂单，需要原子地完成：
1. 买家的金币扣款（`MONEY_COST`）
2. 卖家的挂单摘除（`LIST_DELETE`，在市场的云 List 上）
3. 装备进入买家背包（`LIST_ADD`，在买家的 `abyss_inventory`）
4. 收益进卖家信箱（`MessageSend`）

这些操作由 `MarketEngine.Purchase` 的领域函数返回为 `proposal.cloudOperations`，然后 `PlayerProfileService:Apply` 在 `repository:Commit(..., extraOperations)` 时并入同一个 `BatchCommit` —— 全部或全不。

## 6. 复用要点

| 模式 | 说明 |
|------|------|
| **Gateway 全封装** | 任何 `serverCloud` 调用都必须经过 Gateway，统一错误码、统一回调格式、统一参数校验 |
| **Repository 差异写** | 背包只写变化行，避免整包重写 |
| **跨域事务** | 领域层用 `proposal.cloudOperations` 声明跨域写，Repository 并入 `BatchCommit` |
| **listId 缓存** | `LIST_ADD` 返回的云端 listId 缓存在内存 `listIds[userId]`，后续 MODIFY/DELETE 需要 |
| **revision 防倒退** | `Commit` 强制新状态 revision > 旧状态，防止旧状态覆盖新状态 |

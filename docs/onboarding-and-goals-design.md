# 新手引导与长期目标系统设计草案

状态：**讨论稿，暂不实施**  
适用项目：无尽深渊  
最后更新：2026-08-05

---

## 0. 文档目的

本文记录当前讨论中的两项产品设计：

1. 第一次进入首页开始的新手引导完整流程；
2. 从“单一放置挂机”扩展为可持续追求的战力目标系统。

本阶段只确定产品流程、状态边界和待讨论问题，不修改 Lua、Schema、服务端命令或客户端 UI。

---

## 1. 当前产品问题

当前项目已经具备：

- 首页属性与资源展示；
- 放置挂机和离线收益；
- 装备掉落、装备、强化、升星；
- 可交易装备和交易行；
- 多人常驻服；
- 楼层、章节、Boss、援助和数值模拟基础。

但当前体验存在两个问题：

### 1.1 新玩家缺少完整的第一轮认知

玩家第一次进入首页时，需要先理解：

- 顶部层数、等级、金币、碎片的作用；
- 首页攻击、防御、暴击、攻速、生命、战力的含义；
- 底部首页、背包、图鉴、装备、刷宝、市场各自的用途；
- 进入刷宝后为什么会自动推进；
- 掉落的装备如何使用；
- 可交易装备为什么要保留；
- 交易行如何上架、购买和领取交易结果。

### 1.2 只有放置挂机时，玩家缺少明确的中长期目标

如果玩家只是在首页点击挂机，然后等待数值增长，容易出现：

- 不知道当前战力应该追求什么；
- 不知道下一件装备或下一层有什么意义；
- 不知道为什么需要强化、升星和交易；
- 市场、Boss、无尽模式等系统缺少明确的目标承接；
- 排行榜无法形成可视化的竞争方向。

因此，新手引导和目标系统应一起设计，但分开实施。

---

## 2. 新手引导总流程

目标流程：

```text
第一次进入首页
→ 首页欢迎
→ 顶部资源栏说明
→ 首页属性说明
→ 首页操作按钮说明
→ 底部导航功能说明
→ 进入刷宝
→ 自动开始挂机
→ 第一次掉落不可交易装备
→ 快捷装备
→ 获得可交易装备
→ 进入市场
→ 上架可交易装备
→ 浏览市场
→ 购买教学卖单
→ 领取交易结果
→ 最终总结
→ 努力提升等级吧，后续内容即将为您开放！
```

新手引导不是一次性连续播放的动画，而是可中断、可恢复、可重连的持久化流程。

## 3. 第一阶段：首页认知

### 3.1 欢迎页

文案建议：

```text
欢迎来到无尽深渊
这里是你的冒险首页
接下来我会带你认识各个功能
```

按钮：

```text
开始了解
```

可以允许跳过，但第一次体验默认进入完整引导。

### 3.2 顶部资源栏

当前顶部栏展示：

```text
第 X 层
Lv.X
金币 X
碎片 X
```

引导说明：

- **层数**：当前深渊推进位置，越高通常代表更强的敌人和更好的奖励。
- **等级**：角色成长等级，影响成长和后续开放内容。
- **金币**：用于强化、升星、市场交易和其他成长消耗。
- **碎片**：用于装备或角色相关成长、兑换及后续系统。

这里应采用顶部聚光灯或一次性资源栏说明，不建议为四个资源各弹一个独立窗口。

### 3.3 首页属性区域

当前首页属性卡：

```text
攻击 / 防御 / 暴击 / 攻速 / 生命 / 战力
```

引导说明：

- **攻击**：影响对敌人造成的基础伤害。
- **防御**：降低受到的伤害，提高战斗稳定性。
- **暴击**：影响造成高额伤害的概率或效果。
- **攻速**：影响攻击频率。
- **生命**：显示当前生命和生命上限。
- **战力**：综合衡量当前角色战斗能力的指标。

核心认知：

```text
获得装备
→ 属性提升
→ 战力提升
→ 挑战更高层和更强目标
```

### 3.4 首页操作按钮

当前首页操作：

```text
进入刷宝
开始挂机 / 暂停挂机
领取离线
```

引导说明：

- **进入刷宝**：进入深渊战斗页面。
- **开始挂机**：让角色自动推进、挑战敌人并获得奖励。
- **领取离线**：领取离线期间累计的金币、经验、碎片和装备。

产品规则建议：

- 第一次通过“进入刷宝”进入玩法页后，资源加载完成即自动开始挂机。
- 玩家不需要再点击一次“开始挂机”。
- “开始挂机”按钮仍保留给玩家主动暂停后重新开启。
- 玩家主动暂停后，不应在普通页面切换时被无条件重新开启。

### 3.5 底部导航

当前普通玩家底部导航：

```text
首页 / 背包 / 图鉴 / 装备 / 刷宝 / 市场
```

说明：

- **首页**：查看等级、资源、属性和主要目标。
- **背包**：查看获得的装备、材料和物品。
- **图鉴**：查看发现过的装备和收集进度。
- **装备**：穿戴装备、调整搭配、提升战力。
- **刷宝**：自动挑战深渊并获得掉落。
- **市场**：上架可交易装备，浏览并购买其他装备。

管理员入口不属于普通玩家新手引导。

首页教学阶段不要求玩家逐页操作这些页面，只需要高亮并介绍用途；真正的装备和市场操作在后续步骤中完成。

## 4. 第二阶段：进入刷宝与自动挂机

首页教学完成后显示：

```text
首页功能已经介绍完毕
接下来去深渊开始第一次冒险吧
在那里你会获得第一件装备
```

按钮：

```text
进入深渊
```

流程：

```text
进入 play
→ 等待玩法资源准备
→ 页面显示
→ 统一调用 PlayPresentation 的挂机入口
→ 服务端确认 autoRun
→ 请求 snapshot/delta
```

不应从新手引导模块直接调用第二套 `ServerClient.AutoRun(true)`。所有自动挂机请求都应经过现有的玩法协调器，以保持：

- 请求去重；
- 资源准备；
- 服务端权威校验；
- 背包满、故事门、事件和援助限制；
- 乐观状态和 snapshot 恢复；
- 失败反馈。

## 5. 第三阶段：第一次装备

### 5.1 第一件装备

第一件教学装备建议：

- 服务端保底生成；
- 确保进入背包或可领取区域；
- 对当前角色有明确提升；
- 不可交易；
- 不自动装备；
- 通过快捷装备完成教学。

文案建议：

```text
获得第一件装备
装备可以提升角色属性和战力
现在就把它装备上吧
```

按钮：

```text
快捷装备
```

### 5.2 快捷装备

第一版不建议新增第二套装备领域逻辑。快捷装备按钮可以直接复用：

```text
ServerClient.Equip(itemId)
→ EquipmentEngine.Equip(...)
```

服务端仍需重新验证：

- 装备是否属于当前玩家；
- 装备是否仍存在；
- 装备槽位是否合法；
- 装备是否被锁定；
- 是否仍为当前引导指定装备。

装备成功后：

```text
刷新装备和战力
→ 标记 equipFirstItem
→ 关闭当前教学提示
→ 允许继续挂机
```

---

## 6. 第四阶段：可交易装备

第二件教学装备用于介绍交易系统：

- `tradeable = true`；
- 不自动装备；
- 品质和价格具有吸引力；
- 服务端正常生成和落地；
- 不绕过库存、掉落、事件和 revision 语义。

必须强调当前业务规则：

```text
可交易装备成功装备后，会永久变为不可交易。
```

因此教学流程应避免让玩家先装备第二件装备。

文案建议：

```text
这是一件可交易装备
它可以装备，也可以放到市场出售
这次我们先学习如何进行交易
```

---

## 7. 第五阶段：市场操作教学

### 7.1 打开市场

引导：

```text
进入市场
→ 自动打开交易行
→ 定位到“我的挂单”
→ 高亮新手可交易装备和上架按钮
```

完成条件建议是成功进入市场页，而不是客户端单纯点击按钮。

### 7.2 上架装备

文案：

```text
把这件可交易装备挂到市场上吧
其他玩家可以购买它
```

上架仍必须走正式：

```text
Market.List
→ 交易资格校验
→ 未装备校验
→ 未锁定 / 非援助装备校验
→ 价格校验
→ 创建 listing
```

教程可以显示建议价格，但服务端仍以正式市场规则为准。

成功后标记：

```text
listTradeableItem = true
```

### 7.3 购买教学

不能设计成“玩家上架自己的装备后再自己购买”，因为正常市场应禁止自买。

推荐方案：

```text
玩家上架教学装备 A
→ 系统提供一次性的教学卖单 B
→ 玩家浏览市场
→ 玩家购买 B
→ 领取交易结果
```

系统教学卖单必须：

- 走正常 `Market.Buy` 流程；
- 每个玩家只能购买一次；
- 不产生可刷金币或装备的漏洞；
- 仍检查金币、背包容量、listing 状态和等级准入；
- 不能绕过市场并发锁和服务端结算。

### 7.4 交易结果

如果现有市场购买结果进入交易邮箱：

```text
购买成功
物品已经送入交易邮箱
请打开邮箱领取
```

然后：

```text
市场 → 交易邮箱
→ Market.Collect
→ 物品进入背包
→ 标记 collectMarketMailbox
```

如果现有正式流程是购买后直接进背包，则引导应适配实际规则，不为教程创建第二套交付逻辑。

## 8. 最终收束文案

所有新手步骤完成后，只显示一次：

```text
新手引导完成！

你已经学会了：
查看角色属性和资源
进入深渊自动刷宝
装备掉落物
使用快捷装备
上架可交易装备
购买市场装备
领取交易结果

努力提升等级吧，后续内容即将为您开放！
```

完成后：

- `onboarding.completed = true`；
- 不再自动弹出完整新手引导；
- 后续内容通过等级、楼层、Boss 或其他目标逐步开放。

## 9. 引导状态建议

建议新增独立的、版本化、可持久化的顶层状态，不复用 `storyProgress`、`ruleAcknowledgements` 或客户端 session flag：

```lua
onboarding = {
    version = 1,
    completed = false,
    currentStep = "homeWelcome",
    steps = {
        homeWelcome = false,
        homeTopResources = false,
        homeAttributes = false,
        homeActions = false,
        homeBottomNav = false,
        enterPlay = false,
        startAutoRun = false,
        collectFirstLoot = false,
        equipFirstItem = false,
        listTradeableItem = false,
        openMarket = false,
        buyMarketItem = false,
        collectMarketMailbox = false,
    },
    firstEquipmentItemId = nil,
    tradeableTutorialItemId = nil,
    tutorialListingId = nil,
    tutorialOfferId = nil,
}
```

原则：

- 首页说明步骤可以由客户端交互推进，但最终展示状态仍应可恢复；
- 掉落、装备、上架、购买、领取等关键步骤必须由服务端成功动作推进；
- `currentStep` 用于断线恢复；
- 教学装备和教学 listing ID 只由服务端产生；
- 客户端不直接写教程完成状态。

## 10. 需要继续讨论的核心：玩家目标系统

新手引导只能解决“玩家知道怎么操作”，不能解决“玩家为什么要继续玩”。当前只有放置挂机，因此需要建立可视化的战力目标层。

建议目标系统至少分成以下几类。

### 10.1 深渊推进目标

```text
当前层数
下一层
下一章节 Boss
最高历史层数
```

首页可展示：

```text
距离下一章节 Boss：X 层
推荐战力：X
当前战力：X
预计结果：稳步推进 / 需要提升 / 高风险
```

### 10.2 Boss 深渊

独立的 Boss 目标模块，用于提供明确的短周期挑战：

```text
Boss 深渊
├─ 当前可挑战 Boss
├─ 推荐战力
├─ Boss 特性
├─ 首通奖励
├─ 最高评分
└─ 下一个解锁条件
```

Boss 不应只是普通挂机的换皮。可以增加：

- 特殊机制；
- 限时挑战；
- 受击/无伤/通关时间评价；
- 针对装备构筑的不同要求；
- 每日或每周挑战次数；
- 首通、最高伤害、最快通关记录。

### 10.3 无尽模式

普通深渊负责稳定成长，无尽模式负责展示极限战力：

```text
无尽模式
├─ 当前最高层
├─ 本周最高层
├─ 本次挑战层数
├─ 排名
├─ 赛季奖励
└─ 推荐战力差距
```

无尽模式可以采用：

- 固定赛季周期；
- 统一或半统一增益；
- 最高层优先、通关时间次优的排名；
- 每周结算；
- 赛季奖励和称号；
- 与普通挂机掉落隔离，避免刷资源破坏经济。

### 10.4 排行榜

排行榜不应只展示一个总战力，否则玩家无法知道提升方向。

建议至少拆分：

```text
深渊层数榜
Boss 竞速榜
无尽最高层榜
战力榜
市场成就榜（可选）
```

每个榜单需要明确：

- 排名依据；
- 更新时间；
- 同分排序；
- 赛季或永久；
- 是否允许跨分片；
- 是否使用服务器确认成绩；
- 奖励发放和作弊校验。

### 10.5 战力目标可视化

推荐在首页增加“下一目标”卡片：

```text
下一目标：击败深渊 Boss
当前战力：12,400
推荐战力：15,000
还差：2,600
预计需要：提升 2 件装备
```

点击后进入对应功能：

- 点击 Boss 目标 → Boss 深渊；
- 点击装备差距 → 装备页；
- 点击市场建议 → 市场；
- 点击层数目标 → 刷宝页。

这样放置挂机产出的装备、金币、碎片和市场行为都会被目标系统串起来。

---

## 11. 建议的目标循环

长期循环建议为：

```text
挂机获得资源
→ 装备 / 强化 / 升星
→ 战力提升
→ 挑战更高深渊或 Boss
→ 解锁新内容
→ 进入无尽模式冲榜
→ 获得赛季奖励
→ 继续提升战力
```

目标系统不是单独再加一个页面，而是要让首页、装备、市场、Boss 和排行榜互相导流。

## 12. 当前需要产品确认的问题

以下问题比直接写代码更重要，建议先逐项确定。

### 新手引导

1. 首页教学是否允许跳过？跳过后是否视为完成，还是只隐藏当前步骤？
2. 老玩家已有存档是否默认视为完成？
3. 第一件教学装备是否固定部位、固定品质，还是根据当前缺失槽位动态生成？
4. 可交易教学装备是否由固定掉落产生，还是由服务端专门发放？
5. 教学卖单是系统卖单，还是等待其他玩家真实上架？
6. 购买教学卖单需要玩家先拥有多少金币？
7. 购买后是直接进背包，还是必须经过交易邮箱？
8. 最终提示是否作为一次性奖励面板，还是只显示一句话？

### 玩家目标

1. 普通深渊、Boss 深渊、无尽模式的关系是什么？
2. Boss 深渊是一次性首通、每日挑战，还是赛季挑战？
3. 无尽模式是否与普通挂机共享装备和战力？
4. 无尽模式是否消耗挑战次数或体力？
5. 排行榜按层数、时间、战力还是多榜并存？
6. 排行榜是跨所有常驻服分片，还是单分片排行？
7. 排行榜奖励是否影响主线经济？
8. 战力目标是只展示推荐战力，还是需要显示“差多少装备/多少强化等级”？
9. 后续开放内容按等级、层数、Boss 首通，还是三者组合？
10. 市场交易是成长手段，还是独立的社交/经济玩法？

## 13. 推荐设计顺序

暂不实现代码，建议先完成以下产品决策：

### 第一优先级：确定目标架构

```text
普通深渊 = 稳定成长
Boss 深渊 = 阶段检验
无尽模式 = 极限挑战与排行榜
```

### 第二优先级：确定首页目标卡

首页同时展示：

```text
当前战力
下一目标
推荐战力
差距
前往按钮
```

### 第三优先级：确定新手引导的终点

新手引导不是完成市场操作后就结束，而是要把玩家导向：

```text
下一目标：提升等级和战力
```

最后显示：

```text
努力提升等级吧，后续内容即将为您开放！
```

### 第四优先级：再拆分实现

确定设计后再分别实施：

## 14. 当前结论

当前阶段只保存设计，不实施功能。

推荐产品主线为：

```text
首页认知
→ 自动挂机
→ 第一件装备
→ 快捷装备
→ 可交易装备
→ 市场上架
→ 市场购买
→ 交易结果
→ 战力目标
→ 等级成长
```

最终收束文案：

```text
努力提升等级吧，后续内容即将为您开放！
```

真正需要优先讨论的不是继续堆放置奖励，而是建立：

```text
战力目标
→ Boss 检验
→ 无尽挑战
→ 排行榜竞争
→ 赛季/长期奖励
```

只有这样，挂机、装备和市场才会共同服务于明确的玩家目标。

# 邮件持久化补投与管理员免广告卡

用户反馈正式服个人、全服邮件在离线玩家或新玩家上线后仍为空。当前工具只能访问开发项目，不能验证正式服 UID 的真实投递。此次代码修复和隔离回归不代表正式服已发布或真实玩家已到账。

全服邮件有明确缺陷：批次只保存在 MailService.broadcasts 的实例内存中；发送成功没有写云。另一实例、新实例或重启实例没有广播历史，无法上线补投。StateNormalizer 还遗漏 receivedBroadcasts，领取、删除后的送达记录无法跨存档整理保留，可能重复补投。

实现：全服批次保存到项目统一 authority UID 的云 List（abyss_broadcast_mail_v1），保存失败不提示成功；批次 ID 包含实例随机标识和序号。每个实例从同一云键加载有效批次，支持离线玩家和有效期内新玩家补领。投递保存 receivedBroadcasts 与邮箱内容，重试不重新发奖；跳过过期批次。短缓存与同一在途请求合并减少重复读；投递与过期操作进入玩家操作队列，避免覆盖战斗存档。

个人邮件仍使用独立持久消息队列与旧版本恢复规则。新增打开邮箱时先处理全服、个人待投递任务，再读取列表。临时失败或投递进行中返回 deliveryPending，空列表显示“邮件正在同步，将自动重试”；面板只在待投递或服务端邮箱摘要变化时刷新，关闭/换会话后丢弃迟到回调。该改动覆盖登录暂时失败后空列表不再刷新的路径；尚不能确认该路径就是真实正式服个人邮件丢失原因。

GM 玩家查询区增加“查询投递状态”：读取当前正式游戏运行实例能访问的云任务和存档，显示邮箱数量、个人/全服待投递数量、异常及云读取状态，协议标识 cloud-v1。这里“本实例未在线”也包含在其他实例在线。仅管理员可查询，不发奖、不修改真实玩家存档。旧正式服若没有该命令，说明尚未运行本次修复。

旧全服邮件没有云记录：发送实例已重启且内存丢失后，不能自动恢复，需按原内容重新发放。已有个人云任务保留原 commandId 重试；没有投递证据的已读历史任务不盲目重放。新代码必须发布到正式服并由玩家进入更新后的服务端实例，Maker 开发构建不等于正式服发布。

免广告卡是管理员按 UID 发放/收回的永久身份，不是玩家开关或背包消耗道具。adFree 为服务端存档字段，默认 false；GM 操作经权限检查、独立云队列和 ApplyOnce 持久化，离线与跨实例生效。发放/收回按时间与消息 ID 顺序处理；前一操作失败时后续操作保留，避免重试把收回覆盖为发放。快照/增量同步包含显式 false。

RewardVideo 为统一入口，身份持有者先请求服务端确认再领取，跳过 ShowRewardVideoAd；普通玩家仍走原广告 SDK。覆盖 VIP、扩容、副本额外次数、每日深渊补给、广告礼包和五倍奖励。原领取条件、次数、奖励令牌与防重保持生效。本次没有向真实账号发放身份或测试奖励，也未完成手机广告 SDK 真机验收。

回归用例：offline_broadcast_mail（跨实例、重启、新号、领取删除后防重、失败重试、ID、防止假成功、并行读取、实际 Mail.List）、mail_delivery_refresh（实际邮箱视图的延迟投递、去重、停止刷新、迟到回调）、ad_free_identity（权限、存档与 wire、离线队列、排序重试、服务端身份确认和原领取上限）、ad_free_ui（GM UID、原因、发放、收回、只读）。同时运行已有广告、奖励、个人邮件、网络与存档回归。

# 每日补给与深渊 Boss 战斗修复

范围：三个每日补给木桩和已有深渊 Boss。保留现有战斗场景与剧情实现，四人团本暂不实现。

## 问题与处理

- ActivityView 后面的同名 Update 覆盖了自动攻击、倒计时和结算更新。删除覆盖函数，保留完整每帧更新。
- 活动卡片缓存进入战斗后仍返回“可复用”，场景没有创建。缓存现在比较战斗模式、会话和本地生命周期，只在同一场战斗内复用。
- Boss 未参与战斗中判断，结束与重置也未完整清理。统一战斗生命周期，处理 Boss 命中事件和真实伤害飘字。
- 战斗资源先预加载，再发送开始命令，避免资源未准备好就扣每日次数或深渊票。
- 打桩使用进程 CPU 时钟，存档又截断为整数，无法可靠计时。改为服务端 epoch 秒，旧 CPU 时间会话原次数恢复；客户端持续按服务端开始时间计算剩余时间，重建不延长挑战。
- 开始请求重试复用现有会话；结束等待在途攻击，失败保留场景并间隔两秒重试，重置使旧回调失效。
- Boss 最后一击进入结算时保留命中事件和攻击前状态，背包满导致失败时整笔回滚，重试成功只结算一次。
- Boss 血量原来把 0.3 秒请求限流当成真实攻击速度。改用现有 A/B/C 完整动画的可命中次数估算，保留档位系数和血量下限。
- 独立活动战斗期间暂停服务端登塔战斗更新，包含已排队操作；结束或到期恢复，不改变挂机开关。

## 验证

新增 tests/activity_battles.lua 覆盖三种补给、服务端计时、旧会话恢复、攻击限流、重复开始/结算、三档 Boss、超时失败、最后一击、满背包回滚和登塔暂停/恢复。

新增 tests/activity_battle_presentation.lua 使用真实 ActivityView、ActivityController、GameStateAdapter 和服务端领域逻辑，替换原生控件与传输端口，覆盖列表到场景缓存切换、预加载、自动攻击、倒计时、伤害飘字、普通 Boss 击杀、退出等待、失败重试、重连恢复和迟到回调。

这些是 Lua 逻辑回归，不代表手机实机或原生视觉验收。本地预览未安装且已停止，没有自动启动；手机端仍应验收上述两个入口与完整结算流程。

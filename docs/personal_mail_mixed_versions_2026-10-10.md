# 个人邮件跨版本常驻实例漏投修复

反馈：离线发送后玩家上线未收到，提供 UID 1162201458。Maker 玩家反馈只读查询未找到该 UID 的调试记录；没有发送时间或游戏局 ID，不能确认这笔真实邮件的具体状态。测试使用同 UID 的隔离存档和云消息模拟，没有向真实玩家发送测试奖励。

已复现的代码路径：1.0.15 将 send_mail 放入 abyss_gm_command。较早的常驻实例不支持该 action，却会发送 UNKNOWN_ADMIN_ACTION 失败回执并将任务标为已读。后续新版实例原来只查询未读，无法再次取到。不同实例的云消息可共享，问题出在新旧消费者共用队列和已读状态被当作投递完成。

修复：

- 新发个人邮件进入 abyss_personal_mail_v2，旧实例的通用 GM 轮询不会取走。登录及五秒轮询同时处理个人队列和原 GM 队列，仍由持有玩家会话的实例提交存档。
- 保留未读旧邮件的兼容投递。每个会话扫描一次旧队列的已读个人任务，核对管理员 GM_RESULT 的未读/已读回执。仅对有 UNKNOWN_ADMIN_ACTION 失败回执证据的任务补投；成功回执优先，已成功的历史任务只清理，不重新发奖。没有回执证据的历史已读任务不盲目重放。
- 使用原 commandId/业务订单号和 ApplyOnce。旧任务在存档提交、回执发送成功后删除；删除失败可在后续轮询或新实例重试。成功回执能避免已领取/删除且超出有限 ApplyOnce 历史的邮件被再次发奖。
- 消息值可为表或可解析的 JSON，UID/消息 ID 统一转换。格式不匹配的奖励任务保留为待处理，禁止误确认。取队列临时失败继续登录，由后续轮询重试。
- 增加 UID、commandId、队列及失败阶段日志，不输出邮件正文或附件内容；每会话的兼容扫描缓存在会话解绑后清理。

回归：tests/personal_mail_mixed_versions.lua 原代码失败，新代码通过。覆盖旧消费者无法取到新队列、已读旧失败邮件补投、回执也已读、跨实例/重启、清理失败重试、成功回执优先、无证据历史不重放、轮询不反复扫描历史、云读取失败、原 GM 跨实例发放、JSON/字符串 ID 边界、无效信封不确认和缓存清理。另通过 offline_personal_mail、mail_attachments_badge、offline_recovery、request_lifecycle、stability_economy。

部署要求：收件人的服务端实例须加载此版代码。独立队列让尚未更新的实例不再误消费，但它们不会主动投递新队列中的邮件；进入更新后的实例后才会处理。真实 UID 的收件结果仍需更新后的游戏局日志验证。

# 深渊模式设计文档

状态：实施基线  
适用项目：无尽深渊  
最后更新：2026-08-17

---

## 1. 目标与边界

深渊模式提供一条区别于普通挂机的高期待装备获取循环：

```text
日常玩法获得深渊票
→ 活动页主动选择深渊档位
→ 消耗门票挑战
→ 更高档位获得更高装备掉落概率
→ 挂机途中也可能遇到免费随机深渊
→ 通过深渊柱颜色识别档位
```

本版本遵守以下原则：

1. 仅保留 3 个深渊档位，避免玩家记忆负担。
2. 主动深渊与随机深渊共用同一档位定义、柱体颜色、等级规则与掉落算法。
3. 主动深渊消耗门票；挂机随机深渊完全免费。
4. 所有触发、扣票、档位、掉落和统计均由服务端权威决定。
5. 客户端只负责选择主动档位、显示权威状态与播放表现。
6. 深渊装备进入现有背包、暂存箱和自动处置链路，不建立第二套背包。
7. 背包无法安全接收奖励时，主动深渊不得扣票；随机深渊按现有暂存/自动处置策略处理。

## 2. 三档深渊

| 档位 | ID | 活动倍率 | 柱体颜色 | 视觉色值 | 定位 |
|---|---|---:|---|---|---|
| 裂隙深渊 | `rift` | 1 倍 | 霓虹蓝 | `#29B6FF` | 基础档，较低门槛 |
| 异变深渊 | `mutated` | 2 倍 | 电弧紫 | `#B15CFF` | 中档，高概率掉装 |
| 灾厄深渊 | `calamity` | 3 倍 | 金红 | `#FF8A24` | 最高档，最高掉装概率 |

### 2.1 颜色一致性

颜色来自唯一共享定义 `AbyssDefinitions`：

- 活动页档位卡边框、倍数按钮、概率提示使用该颜色；
- 主动结算动画的深渊柱使用该颜色；
- 挂机随机深渊柱使用该颜色；
- 奖励弹窗的来源标签使用该颜色；
- 服务端事件只传 `gradeId`，客户端从共享定义解析颜色，避免服务端和客户端色值漂移。

### 2.2 等级解锁

| 玩家等级 | 可用主动档位 | 随机深渊可能档位 |
|---:|---|---|
| 1–19 | 裂隙 | 裂隙 |
| 20–39 | 裂隙、异变 | 裂隙、异变 |
| 40+ | 全部 | 全部 |

未解锁档位在活动页可见但不可选择，并明确显示解锁等级。

## 3. 深渊票与等级递增

### 3.1 初始资源

- 新玩家初始深渊票：`120`。
- 深渊票是 `abyss.tickets` 的服务端权威整数，不接受客户端直接改值。
- 客户端背包可将其投影为资源道具，但不能作为扣费真源。

### 3.2 每 10 级直接变动

主动深渊的 1 倍基础门票公式：

```text
levelBand = floor((玩家等级 - 1) / 10)
baseCost = 40 + levelBand × 10
```

示例：

| 玩家等级 | 1 倍 | 2 倍 | 3 倍 |
|---:|---:|---:|---:|
| 1–10 | 40 | 80 | 120 |
| 11–20 | 50 | 100 | 150 |
| 21–30 | 60 | 120 | 180 |
| 31–40 | 70 | 140 | 210 |
| 41–50 | 80 | 160 | 240 |

这是一条阶梯函数：跨过 10 级门槛后直接采用新价格，不做线性插值。

### 3.3 扣费规则

```text
ticketCost = baseCost × grade.multiplier
```

服务端按请求到达时的真实等级重新计算，不信任客户端提交的价格。扣票和奖励结算必须在同一次权威事务内完成；结算失败则不扣票。

## 4. 装备掉落模型

### 4.1 掉装概率

每次深渊最多生成 1 件装备：

| 档位 | 主动深渊掉装率 | 随机深渊掉装率 |
|---|---:|---:|
| 裂隙 | 35% | 35% |
| 异变 | 65% | 65% |
| 灾厄 | 90% | 90% |

“花得越多，爆装概率越大”直接体现在 1/2/3 倍对应的 35%/65%/90%。倍率不复制奖励次数，避免 3 倍消耗变成三次普通抽取；它提升的是单次深渊的掉装确定性与品质倾向。

### 4.2 品质倾向

深渊只会产出玩家当前进度已解锁的品质。未解锁品质的权重向当前最高已解锁品质回流，不会丢失概率。

三档品质权重方向：

- 裂隙：接近精英怪掉落，重点为稀有/神器；
- 异变：接近 Boss 掉落，提高传说及以上权重；
- 灾厄：进一步压低低品质，提高史诗/神话权重，但仍受现有品质解锁楼层限制。

装备等级使用玩家当前有效进度：

```text
equipmentLevel = max(玩家等级, 当前最高楼层)
```

最终实现中由共享规则统一换算为掉落参考层，主动与随机深渊不各自维护一套品质表。

### 4.3 保底

深渊拥有独立软保底计数 `abyss.dryStreak`：

- 未掉装备：`dryStreak + 1`；
- 掉出装备：清零；
- 连续 5 次未掉装备后，第 6 次强制掉落；
- 主动和随机深渊共用该计数，免费随机深渊也能推进或触发保底；
- 该保底只保证“有装备”，不保证指定稀有度。

### 4.4 基础奖励

无论是否掉装备，完成深渊均给予少量碎片：

| 档位 | 碎片 |
|---|---:|
| 裂隙 | 12 |
| 异变 | 24 |
| 灾厄 | 40 |

基础奖励用于避免“完全空手”，但不替代普通挂机的主要经济产出。

## 5. 活动页主动深渊

### 5.1 入口

活动页“热门活动”中的原“深渊远征”占位改为正式“深渊模式”卡片，显示：

- 当前深渊票；
- 玩家等级对应的 1 倍基础价格；
- 3 个档位及颜色；
- 当前选中档位；
- 本次实际消耗；
- 装备掉落概率；
- 等级解锁条件；
- “进入深渊”按钮。

### 5.2 操作流程

```text
玩家选择档位
→ 客户端发送 gradeId
→ 服务端校验档位/等级/门票/背包策略
→ 服务端计算真实价格并原子扣票
→ 服务端权威投掷掉装与品质
→ 奖励进入背包/暂存/自动处置链路
→ 返回 abyss_completed 事件
→ 客户端播放对应颜色深渊柱与奖励反馈
```

客户端不提交价格、掉率、品质、奖励或随机数。

### 5.3 防连点和失败语义

- 客户端请求在途期间禁用进入按钮；
- 服务端命令使用 progression 级限流；
- 票不足返回 `ABYSS_TICKET_INSUFFICIENT`；
- 档位未解锁返回 `ABYSS_GRADE_LOCKED`；
- 背包无法安全接收返回 `INVENTORY_FULL`；
- 所有失败均不扣票、不增长统计、不推进保底。

## 6. 挂机随机深渊

### 6.1 触发时机

仅在在线自动挂机、准备进入普通战斗时由服务端投掷：

- 基础触发率：`4%`；
- 只替换普通怪遭遇，不替换精英、Boss、章节 Boss、剧情门和交互事件；
- 每次触发后至少间隔 `20` 个已结算战斗，避免连续刷出；
- 离线批量收益不触发随机深渊，避免离线模拟产生不可见的高价值随机事件。

持久化字段 `abyss.randomCooldownBattles` 记录剩余冷却战斗数，重连不会重置。

### 6.2 免费规则

- 不消耗深渊票；
- 不改变活动页价格；
- 与主动深渊共用档位掉率、品质倾向和保底；
- 统计记入 `randomRuns`，与 `activeRuns` 分开。

### 6.3 随机档位

服务端先按玩家等级过滤未解锁档位，再按以下基础权重抽取：

| 档位 | 权重 |
|---|---:|
| 裂隙 | 70 |
| 异变 | 25 |
| 灾厄 | 5 |

未解锁档位权重回流到裂隙档，不会出现客户端能看到但无法结算的柱子。

### 6.4 表现顺序

```text
服务端决定随机深渊
→ abyss_random_spawned 事件携带 gradeId
→ 当前遭遇标记 abyssGradeId / abyssSource
→ 客户端用共享色表显示深渊柱
→ 自动战斗沿用现有挂机节奏
→ 胜利后服务端按深渊规则结算
→ abyss_completed 事件显示奖励
```

随机深渊战斗失败时不发奖励、不推进保底；冷却仍保留，防止玩家通过失败重刷档位。

## 7. 权威状态模型

顶层新增 `abyss`：

```lua
abyss = {
    tickets = 120,
    dryStreak = 0,
    activeRuns = 0,
    randomRuns = 0,
    equipmentDrops = 0,
    highestGrade = "rift",
    randomCooldownBattles = 0,
    currentRandom = nil,
}
```

`currentRandom` 仅在随机深渊遭遇进行中存在：

```lua
currentRandom = {
    runId = "abyss.<revision>.<time>",
    gradeId = "rift",
    source = "random",
    floor = 1,
    createdAt = 0,
}
```

### 7.1 字段职责

- `tickets`：主动入口唯一扣费真源；
- `dryStreak`：跨主动/随机共享的掉装保底；
- `activeRuns`：已完成主动深渊次数；
- `randomRuns`：已完成免费随机深渊次数；
- `equipmentDrops`：深渊实际产出装备总数；
- `highestGrade`：历史完成的最高档位；
- `randomCooldownBattles`：在线随机触发冷却；
- `currentRandom`：重连恢复当前随机深渊表现和结算上下文。

### 7.2 状态链

必须贯穿：

```text
StateFactory
→ StateNormalizer
→ GameStateContracts
→ GameStateDefinitions
→ GameStateBoundarySchemas
→ GameStatePersistence
→ PlayerTransition
→ GameStateWire
→ GameStateAdapter
```

嵌套 `abyss` 在客户端 delta 应整体替换，避免 `currentRandom=nil` 时旧对象残留。

状态 schema 版本从 7 升至 8；旧档通过 normalizer 自动补齐默认值，不重置其他状态。

## 8. 命令与事件契约

### 8.1 命令

新增：

```text
Activity.EnterAbyss { gradeId }
```

服务端只接受共享定义中的 `gradeId`，payload 不允许未知字段。

### 8.2 事件

新增事件：

1. `abyss_started`
   - `runId`
   - `source`: `activity | random`
   - `gradeId`
   - `ticketCost`
   - `dropChance`

2. `abyss_random_spawned`
   - `runId`
   - `gradeId`
   - `floor`

3. `abyss_completed`
   - `runId`
   - `source`
   - `gradeId`
   - `ticketCost`
   - `fragments`
   - `equipmentDropped`
   - `itemId`（有掉落时）
   - `rarity`（有掉落时）
   - `dryStreak`

现有 `equipment_drop`、`loot_dropped`、`loot_settled` 仍负责通用装备反馈；`abyss_completed` 负责深渊玩法摘要。

旧的 `abyss_echo` 仅是普通随机事件碎片奖励，不作为新深渊模式入口。为避免破坏兼容性，本版本保留其原语义。

## 9. UI 与表现

### 9.1 活动页

遵循现有 BrawlForge 深蓝 HUD：

- 锐角结构、黑色外边框、零模糊硬阴影；
- 档位选中态使用该档位颜色边框；
- 票数、价格、概率保持单行；
- 未解锁按钮灰化并显示“Lv.20 / Lv.40 解锁”；
- 进入按钮显示真实消耗，如“进入深渊 · 120票”。

### 9.2 深渊柱

柱体使用 UI 组件绘制，不依赖新增位图：

- 深色柱芯；
- 档位色外框；
- 同色纵向渐变能量；
- 2 层硬边发光；
- 顶部显示档位名；
- 主动结算和挂机随机遭遇调用同一构建函数。

### 9.3 奖励反馈

- 未掉装备：显示碎片奖励与当前保底进度；
- 掉出装备：复用现有装备奖励卡；
- 暂存箱/自动处置：显示现有 `loot_settled` 结果；
- 随机深渊额外显示“免费遭遇”，避免玩家误以为被扣票。

## 10. 日志与验证

首轮实现保留关键服务端日志：

```text
[Abyss] enter uid/source/grade/level/cost
[Abyss] random spawn floor/grade/cooldown
[Abyss] settle source/grade/dropped/rarity/dryStreak
```

验证矩阵：

1. Lv.1/10/11/20/21/40/41 价格阶梯正确；
2. 1/2/3 倍颜色、价格、掉率一致；
3. 未解锁档位服务端拒绝；
4. 门票不足不扣票；
5. 背包满且无自动处置时不扣票；
6. 主动深渊成功后票、统计、保底和奖励一次性更新；
7. 随机深渊免费且只替换普通遭遇；
8. 冷却期间不重复触发；
9. 重连后票、统计、冷却和当前随机深渊一致；
10. 第 6 次必掉保底正确；
11. snapshot/delta/event schema 均通过；
12. 主动和随机柱体颜色来自同一共享定义。

## 11. 实现顺序

```text
1. AbyssDefinitions：档位、颜色、价格、掉率、等级解锁
2. abyss 权威状态、schema、持久化、delta、客户端投影
3. AbyssEngine：主动扣票与统一奖励结算
4. Activity.EnterAbyss 命令与活动页入口
5. 在线挂机随机触发与遭遇标记
6. 共用深渊柱、奖励摘要和装备反馈
7. LSP、构建、状态边界与数值测试
```

本文件是本轮实现的固定口径；后续代码不得在客户端复制价格、掉率或档位表。

## 12. 深渊票福利与激励广告扩展

### 12.1 深渊票正式道具

- 深渊票继续使用服务端权威计数 `abyss.tickets`，不占装备背包格。
- 客户端背包将其投影为 `abyss_ticket`，使用独立蓝青色裂隙晶核图标，不再复用许愿券图标。
- 邮件、GM、签到、等级里程碑、章节通关和深渊结算均通过统一服务端接口发放。

### 12.2 基础获取渠道

- 新手七日签到合计发放 240 张。
- 30 日循环签到每日提供基础深渊票，并在周节点和第 30 天提高奖励。
- Lv.5、10、20、30、40 及后续关键等级发放一次性成长奖励。
- 每通关 10 层发放与当前等级档位匹配的深渊票。
- 主动深渊返还实际消耗的 25%；免费随机深渊发放对应档位当前票价的 50%。

### 12.3 激励广告五倍规则

所有带“普通领取 / 激励广告领取”选项的奖励统一遵循：

```text
普通领取总收益 = 1 倍基础奖励
完整观看广告后的总收益 = 5 倍基础奖励
广告额外部分 = 4 倍基础奖励
```

“5 倍”指最终到账总量为普通收益的 5 倍，不是基础奖励之外再增加 5 倍。客户端只展示服务端给出的基础奖励与五倍预览，不得自行乘算或发奖。

广告失败、提前关闭、请求未受理、回调超时或服务端拒绝时均不发放广告额外部分，玩家仍可选择普通领取。每个奖励账本只能成功领取一次。

### 12.4 适用范围

首期支持五倍领取的待领取奖励：

- 签到奖励；
- 等级里程碑奖励；
- 每 10 层章节通关奖励；
- 任务奖励；
- 深渊结算中的返还票券与碎片。

离线收益不提供激励广告五倍。装备、装备品质、装备数量、深渊保底进度和即时战斗掉落不参与五倍复制。

### 12.5 广告专属高奖励

广告专属补给没有普通领取入口：

- 每日深渊补给：一天最多观看 3 次广告；
- 每次发放当前灾厄深渊票价的 80%（向上取整）；
- 活动页只保留这一枚补给按钮，不再展示周箱和等级豪礼入口。

所有广告资格、周期限制、奖励数量和幂等记录均由服务端保存和校验。
